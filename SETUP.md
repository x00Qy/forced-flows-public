# SETUP — forced-flows

Everything needed to run this repository from a clean machine and reproduce every committed
result. For what the project found, read [`README.md`](README.md) and [`RESULTS.md`](RESULTS.md).

---

## 1. Python version

**3.10 or newer.** Verified on **CPython 3.13.6** (Windows), which produced every file in
`results/`.

## 2. Install

```bash
pip install -r requirements.txt
git clone https://github.com/x00Qy/yalgo-core    # beside this repository
pip install -e ../yalgo-core
```

**All three lines are required.** `yalgo_core` is a **separate repository, not a PyPI package** —
it holds the shared cost model. If it is missing, `src/require_yalgo_core.py` raises with the exact
`pip install -e` command rather than a bare `ModuleNotFoundError`.

Any path works; `../yalgo-core` is a convention, not a requirement. Nothing depends on the literal
path except the text of the error message.

`requirements.txt` pins `numpy==2.4.6`, `scipy==1.18.0`, `pypdf==6.16.1`. **A clean virtualenv
resolving numpy 2.5.3 / scipy 1.18.1 reproduced every committed result byte-identically apart from
the run timestamp** (verified 2026-09-22), so the pins are known-good rather than load-bearing.

**`xlrd` and `openpyxl` are NOT required.** No committed script imports them. An earlier revision
of `requirements.txt` listed them in error; the reason is recorded in that file.

### Verify

```bash
python -c "from require_yalgo_core import round_trip_cost_bps; print('ok')"   # from src/
python src/gate_sip_timing.py --dry-run
```

The second runs eight validation arms on synthetic data with known answers and prints
`ALL ARMS PASS`. It touches no real data and needs no downloads.

## 3. Where data files must sit

Everything lives under `data/`. **Two kinds:**

> **Which clone you have decides whether the first kind is there.** In the **private** repository
> the derived files below are committed, so a clone has them. In the **public** mirror **nothing
> under `data/` is committed at all** — the whole tree is gitignored, because NSE and NSE Indices
> prohibit redistribution. There, every file below has to be fetched, and each script tells you
> which one is missing and which fetcher produces it rather than failing with a traceback
> (`src/require_data.py`).

**Derived files** — present after clone of the private repo; fetched from scratch in the public
mirror:

| file | what |
|---|---|
| `fo_secban_2015_2026.csv` | consolidated F&O ban archive, 2,893 trading days |
| `nifty500_daily_2015_2026.csv` | NIFTY 500 daily open/close, 2,884 days |
| `nse_cash_turnover_daily.csv` | daily NSE cash turnover, 2,893 days |
| `corpactions_banlist_2015_2026.csv` | 2,096 corporate actions for the 141 ban-list symbols |
| `amfi_sip_monthly.csv` | monthly SIP contribution, 2024-06 → 2026-08 |
| `amfi_monthly_notes_index.csv` | AMFI Monthly Note PDF URLs (content-hashed, cannot be constructed) |
| `sip_form_dates.csv` | SIP dates enumerated on published AMC application forms |
| `nse_index_recon_announcements_2026-09-21.csv` | Phase 1 announcement archive |

**Gitignored raw caches** — absent after clone, regenerated by script:

| directory | regenerate with | size / time |
|---|---|---|
| `data/fo_secban/` | `python src/fetch_secban.py` | ~2,900 files, ~15 min |
| `data/bhavcopy/` | `python src/fetch_cash_bhavcopy.py` | ~2,900 zips, ~40 min |
| `data/index_close/` | `python src/fetch_index_close.py` | ~2,900 files, ~15 min |
| `data/corpactions/` | `python src/fetch_corpactions.py` | 141 JSON, ~3 min |
| `data/amfi_notes/` | `python src/precheck_sip_timing.py` | 27 PDFs, ~1 min |
| `data/sip_forms/` | `python src/fetch_sip_forms.py` | 9 PDFs, ~1 min |

**They are gitignored because NSE and NSE Indices prohibit redistribution of their data** — both
clauses are quoted with links in `README.md`. Not a size decision.

**Every fetcher caches and is resumable.** A re-run costs nothing for files already on disk, and a
404 is cached too so re-runs do not re-probe every holiday.

> **Do not raise fetcher concurrency.** All fetchers use three workers and a 0.35s pause (one
> worker and 1.0s for the AMFI API). NSE blocks addresses that pull too fast, and a block costs far
> more than the time saved.

## 4. Running the key scripts

Run from the repository root. Scripts resolve paths relative to their own location, so the working
directory does not matter, but `src/` must be importable — running `python src/<name>.py` handles
that.

**Cheapest headline — the Phase 3 gate.** One input, under a minute:

```bash
python src/fetch_index_close.py     # only if data/nifty500_daily_2015_2026.csv is absent
python src/gate_sip_timing.py
```

Expect `MDE 53.20 bps` against a `16.9664 bps` bar and `VERDICT: CLOSE AS UNDERPOWERED`.

**The Phase 2 gate.** Needs the bhavcopy, so budget ~40 minutes of downloading the first time:

```bash
python src/fetch_secban.py
python src/consolidate_secban.py
python src/fetch_cash_bhavcopy.py
python src/fetch_corpactions.py
python src/gate_ban_list_nuisance.py
```

Expect `MDE 120.42 bps` against a `71.35 bps` bar and `CLOSE_UNDERPOWERED`.

**The pre-checks**, both of which read only committed files:

```bash
python src/precheck_index_recon.py    # Phase 1
python src/precheck_ban_list.py       # Phase 2 (verdict later superseded -- see RESULTS.md)
python src/precheck_sip_timing.py     # Phase 3 (fetches 27 AMFI PDFs on first run)
```

**The interval-method calibration**, which chose the bootstrap percentile the Phase 2 gate uses:

```bash
python src/calibrate_interval_method.py
```

~5 minutes. It checkpoints each grid cell to `results/interval_cov/` and resumes from there, so an
interrupted run costs only the cell it was in. Delete that directory to force a clean re-run.

**Every gate and pre-check runs a synthetic dry run first** and refuses to proceed if any arm
fails. `--dry-run` runs only that part.

### Reproducing a committed result exactly

Outputs carry a run timestamp, so compare with it stripped:

```bash
python src/precheck_ban_list.py > /tmp/new.txt
diff <(sed -E 's/20..-..-..T[0-9:]+Z//' results/precheck_ban_list_2026-09-21.txt) \
     <(sed -E 's/20..-..-..T[0-9:]+Z//' /tmp/new.txt)
```

Verified 2026-09-22: identical for `precheck_index_recon` and `precheck_ban_list`.

## 5. Type checking

```bash
MYPYPATH=/path/to/yalgo-core mypy --strict src/<file>.py
```

`mypy --strict` is clean across this repository **with `MYPYPATH` set**. Without it, mypy reports
`import-not-found` for `yalgo_core`, because **mypy cannot follow a PEP 660 editable install**.
That error is expected and is not a defect — verified 2026-09-22 that setting `MYPYPATH` resolves
it and the check passes clean.

## 6. If something fails

| symptom | cause | fix |
|---|---|---|
| `ModuleNotFoundError` naming `yalgo_core` with a long message | the sibling package is not installed | run the `pip install -e` line it prints |
| `import-not-found` for `yalgo_core` from mypy only | PEP 660 editable install | set `MYPYPATH`; runtime is unaffected |
| a fetcher stalls or returns many `none` | NSE is rate-limiting or blocking | stop, wait, re-run — the cache makes it resumable. **Do not raise concurrency.** |
| a `DATA NOT PRESENT` block and exit 2 | an input under `data/` is absent | **expected in the public mirror and in any fresh clone.** The block names the file and the fetcher; run that. In the private repo it means a committed file was deleted |
| `FileNotFoundError` **with a traceback** | a path OUTSIDE `data/` is missing | a real defect, not absent input — `require_data.guard` deliberately does not swallow it |
| a dry-run arm prints `*** FAIL ***` | a real defect | the script refuses to run; do not bypass it |
